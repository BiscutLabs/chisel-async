# chisel-async 0.1.0-RC1

First release candidate of chisel-async: typed asynchronous hardware components,
digital models and verification tools for Chisel.

## Included

- Four-phase bundled-data stages, FIFOs, controlled mux/demux, fork/join,
  registered forks, initial tokens and arbitration.
- Native standard and phase-decoupled Click stages, buffers and FIFOs,
  including initialized feedback and explicit pulse/setup/hold timing contracts.
- Return-to-zero dual-rail components, two-phase interfaces and protocol
  converters, plus explicit bridges to Chisel's clocked `Decoupled` interface.
- Typed channel helpers, independently bounded primitive delays, optimized
  contract export, ASIC cell-binding interfaces and the ScalaTest `AsyncTest` helper.
- Runnable adder, tagged Click adder, GCD and feedback-ring examples; user guides
  and generated Scala API documentation.

## Download and use

RC1 is an **unsigned GitHub prerelease**, not a Maven Central publication.
Download `chisel-async-0.1.0-RC1-maven.zip`, extract it, and add its `maven` directory
as a local sbt resolver:

```scala
resolvers += "chisel-async RC1" at file("/absolute/path/to/extracted/maven").toURI.toString
libraryDependencies += "io.github.biscutlabs" %% "chisel-async" % "0.1.0-RC1"
```

The ZIP contains the binary, sources, Scaladoc JAR and POM in Maven layout.
Those four files are also attached individually. `SHA256SUMS` covers the attached
distribution and evidence; `manifest.json` binds the JARs/POM to the source commit.
Normal transitive dependencies still resolve from Maven Central. Keep the
matching Chisel compiler plugin in your project.

The candidate is built once on Linux. The release workflow requires complete
native Windows/Linux qualification and consumption of that same JAR on both hosts
before publishing these assets. The attached `consumer-Windows.json` and
`consumer-Linux.json` identify the tested hashes. Full logs remain in Actions.

## Compatibility

Scala **2.13.18**, Chisel/compiler plugin **7.16.0**, firtool **1.160.0**,
JDK **21**, sbt **1.12.4**, Icarus **13**, and Verilator **5.046**.
Native qualification targets Ubuntu **24.04** and Windows **2025**; macOS is deferred.

For users of earlier development snapshots, Click stage named payload arguments
are now `inGen` and `outGen` instead of `a` and `b`. Positional argument order is
unchanged. Use `twoPhaseInput`/`twoPhaseOutput` to declare and register ports, and
`asyncChild` to share the parent's reset domain.

## Scope and remaining work

This candidate validates digital behavior within declared model bounds. It does
not provide complete physical timing, metastability or QDI layout qualification.
ASIC mapping requires characterized technology cells; the GF180 reference remains
partial. Click propagation contracts export correctly, but the OpenSTA path
checker rejects Click until pulse and setup/hold analysis is available.
Native Click routing beyond stages/FIFOs is not included; the existing `TwoPhase*`
routing family uses four-phase cores and adapters. Maven Central signing and
publication will follow separately.
