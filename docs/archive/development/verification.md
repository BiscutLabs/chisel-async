# Verification method and acceptance criteria

> Historical development record. For current usage, read the [user documentation](../../index.md).

Development regression campaign, October 5, 2026. Scope: zero-delay behavioral storage, the withdrawn structural experiment, pure transform and resettable C-element on Icarus 13.0. The [external review response](review-response.md) records a directed internal-delay counterexample; historical zero-delay successes do not qualify that controller. No physical delay, hazard freedom, QDI or metastability claim follows. This is not a held-out release experiment.

The separate [published-controller comparison](controller-comparison.md) adds explicit internal cell delays, a Muller reference, capacity/validity distinctions, two activated fault controls and a frozen 300-seed sweep. Its early-validity monitor intentionally differs from this document's full-return behavioral contract. Both campaigns remain required; their passing counts are not interchangeable.

## Claims and independent expectations

The implementations are the packaged behavioral storage resource and a separate Chisel composition of latch primitives. `verification/reference.py` implements a four-edge protocol contract and a queue-based token ledger without importing production controller code. Both implementations use the same external tests. The transform fixture independently maps accepted integer payloads through XOR 0x55 in the ledger; output observations are compared unmodified. Drivers generate environment actions; passive observers never drive signals or postpone capture to make a check pass. Payload equality, conservation, capacity and reset outcomes follow the published contract, not expected traces generated by the DUT.

Input acknowledgement rising accepts a token. Output acknowledgement rising delivers it; output acknowledgement falling releases reserved capacity. Reset aborts undelivered tokens and starts a new epoch. Requests awaiting acceptance are tracked by the channel monitor but are not counted as accepted tokens. The ledger checks `accepted = delivered + outstanding + aborted`, and each completed test must finish with idle channels and no reserved storage.

The C-element uses an independently expressed characteristic equation. Its 256 four-transition Boolean sequences cover 1,024 checked transitions; five additional observations cover selected unknown/reset behavior. This is finite state/input evidence, not an analog model.

## Observation policy

Control listeners record every value-change callback exposed by the qualified engine. Payload is sampled in cocotb's read-only phase after request-time settling. Separate data listeners remain armed during stalls and the return-to-idle phase; a later excursion fails even if it recovers before the driver samples again. Initial data settling at the request timestamp is allowed by the behavioral contract. These checks do not establish arbitrary internal delta-event observability or gate-level hazard freedom. Drivers assert reset before withdrawing held signals.

Trace timestamps are exact integer picoseconds, matching the selected fixture precision. They measure modeled event order only. Stream delays use fixed source/sink seeds with the recorded Python version; they are test stimulus, not process variation or a physical delay distribution. Trace logs retain the realized events.

## Required experiments

| Claim | Required activity | Falsifier/control |
| --- | --- | --- |
| Stream preservation | 40 accepted, delivered and returned tokens per buffer/pipeline fixture, including equal values; final idle | Invert captured payload: `PAYLOAD_MISMATCH`. |
| Legal handshake and stable data | Passive listeners active throughout each buffer test | Withdraw request for 200 ps: `REQUEST_WITHDRAWN`; invert data for 200 ps during hold: `DATA_CHANGED_DURING_HANDSHAKE`. |
| Payload wiring | Walking ones and zeros at every bit in 8-bit, 65-bit and 22-bit aggregate payloads; each aggregate leaf varies independently | Swap bits 1/2 or wide bits 32/33: `PAYLOAD_MISMATCH`. |
| Reset/abort/restart | Five selected phases; full one/two-stage capacity plus an unaccepted offer; zeroed data and completed fresh traffic | Reset data to ones: `RESET_DATA_MISMATCH`; exact accepted/delivered/aborted accounting is required. |
| Bounded event ordering | 18 legal two-token orders with equal and distinct values, 68 unique prefixes followed by reset/restart, six boundary cases per single-buffer fixture | Any illegal edge, capacity violation, payload mismatch or inconsistent reset count fails. |
| Structural acknowledgement isolation | Pending second input while the output remains full; same tests as behavioral storage | Reopen the acknowledgement latch based on input request: `CAPACITY_EXCEEDED`. This reproduces a defect found during development. |
| Pure transform | Stream, bit patterns, equal values, stalls and reset on the XOR stage | Bypass the emitted XOR: `PAYLOAD_MISMATCH`. |
| Checker/harness integrity | Exact XML case inventory, positive activity/coverage, fresh evidence, matching trace inventory and expected control diagnostics | Missing cases, skipped cases, unrelated errors, stale reports and incomplete activity are rejected by Python tests. |

The two-token enumeration has eight environment actions: input offers `p0/p1`, input request returns `r0/r1`, output acknowledgements `a0/a1`, and output acknowledgement returns `z0/z1`. Prerequisites are declared separately from production behavior. In particular, a second request can wait while storage is full, but its request cannot return before acceptance after `z0`. There are exactly 18 linear extensions and 68 distinct prefixes under these assumptions. This is not exhaustive over unbounded streams, all delays, pipeline networks or independent resets.

Functional boundary cases vary source request return versus sink acknowledgement, and next input offer versus prior output acknowledgement return, at -1/0/+1 ps. The separate [timing/compiler campaign](timing-and-export.md) tests exact-fs setup/hold, pulse filtering, reset cancellation, transaction identity and endpoint preservation. These experiments missed the structural controller's internal race. The new directed counterexample delays one release-enable branch, retains the actual emitted controller equations, and requires a duplicate offer after exactly one acceptance and delivery. A paired baseline, strict diagnostic, annotated-source hashes and VCD make the failure inspectable. It is not a reproduction of the external random-seed campaign.

## Evidence and release discipline

Run the README commands. The functional campaign requires 52 positive tests and eight expected rejections. The clean consumer requires 18 positives across behavioral buffer, structural buffer and transform, plus seven controls. The timing campaign adds seven passing cases, two intended timing violations and five corrupted-model controls, also repeated by the clean consumer. Each control runs one named test and must produce an assertion whose first diagnostic line exactly matches its required checker. A crash, timeout or another assertion cannot satisfy the control.

Each case writes `*.trace.jsonl` and `*.evidence.json`, including observations, coverage, token counts, edge counts and reset epochs where applicable. The runner invalidates prior evidence before execution, checks required activity and trace ordering, and includes hashes in `report.json`. If execution stops on a failed run, the report identifies that run and remaining unexecuted runs. XML and logs retain the failing details. CI uploads this evidence; ordinary source control excludes generated output.

Before a release, freeze the implementation, oracle/checker revisions, case inventory, toolchain and acceptance criteria before evaluating an independently reviewed campaign. Do not relabel development cases as held-out evidence or infer a defect probability from repeated deterministic runs. Windows/Linux evidence is recorded in [qualification status](qualification.md); macOS is explicitly deferred. The separate [frozen L0 campaign and fresh-context agent review](l0-acceptance.md) close the Windows/Linux foundation gate; this development corpus alone does not. The digital timing and pinned compiler route have their own executed controls, detailed in the linked contract.

## Comparison with inspected upstream tests

These are source inspections, not claims that their suites were executed or that the projects share our scope. No upstream implementation or test code was copied.

| Pinned source | Observation and lesson |

| [ASYNC-Chisel `1af2cf4`](https://github.com/Jilin-Zhang/ASYNC-Chisel/tree/1af2cf4f621aa77657cab25858cc4a038a7291d6/testbench) | Its example benches include FIFO, fork/join, arithmetic and feedback. The FIFO uses fixed waits and printed results; the inspected GCD/Fibonacci benches do not assert expected results. Preserve useful composition scenarios while enforcing failures and activity. |
| [chisel-click `ae87f67`](https://github.com/KasperHesse/chisel-click/tree/ae87f671bce101a22ea3ec40ad0e9e18a8cc3a28/src/test) | Directed component checks include staggered fork acknowledgement; the Scala GCD test compares 100 operand pairs against a software algorithm. Reuse the ideas of adversarial schedules and independent arithmetic oracles, while respecting its different two-phase protocol. |
| [ACT simlib `d92b0d9`](https://github.com/asyncvlsi/actsim/tree/d92b0d99a0eb214acf3ff03fb484039fb40bf4cb/simlib/test) | Separate model/DUT scoreboard inputs and deliberate mismatch fixtures test the checker itself. Retain diagnostic regressions, but justify expected outcomes independently instead of blessing current DUT output. |

[Workcraft's verification guidance](https://workcraft.org/help/verification) distinguishes conformance, deadlock freedom and output persistency under an explicit environment. Those distinctions inform our properties; running these simulation tests is not a Workcraft proof. Likewise, [cocotb's observation phases](https://docs.cocotb.org/en/v2.0.0/timing_model.html) motivate a stated sampling policy rather than assuming an edge callback means all downstream values have settled.
